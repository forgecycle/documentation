# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Practitioners: developers who already run coding-agent CLIs (OpenCode, Codex
CLI, Claude Code CLI, Antigravity's `agy`) and who install ForgeCycle, run it,
and return mid-task to look up a command, a configuration key, a schema, or a
recovery step.

## Product Purpose

This site documents ForgeCycle, an artifact-driven development loop. Success is
a reader finding the exact command, key, or recovery path quickly, and
understanding the loop well enough to trust running it unattended.

## Positioning

ForgeCycle splits work across four roles (Decomposer, Planner, Builder,
Reviewer), each a fresh agent invocation routed to the model that suits it.
Context travels only through immutable Markdown handoffs and Git commits, not
vendor session history. Reviewer is the only completion authority; Builder is
the only role that changes the repository, one commit per turn. Task runs work
in isolated Git worktrees and every stop names its reason and next command.

## Operating Context

Readers arrive from a terminal session, often while a task run is stopped or
waiting for approval. ForgeCycle also ships a local, read-only dashboard
(`forgecycle serve`) usable on desktop and phone.

## Capabilities and Constraints

- Astro Starlight site deployed to GitHub Pages at `/documentation/`.
- Pages under `src/content/docs/{start,concepts,guides,reference}/`,
  `public/schemas/`, and `src/generated/` are generated by
  `scripts/import.mjs` from the private source repository and must never be
  hand-edited. Design must work on arbitrary imported Markdown: long prose,
  ASCII diagrams in `text` code blocks, wide tables, CLI references.
- The landing page, site configuration, and import script are maintained here.
- Version shown comes from `src/generated/release.json`.

## Brand Commitments

None binding. The existing favicon/logo may be replaced.

## Evidence on Hand

Real content only: the imported docs, the CLI help, JSON schemas, and the
release version. No customers, testimonials, benchmarks, or adoption numbers
exist; do not invent them.

## Product Principles

1. Findability first: a command or key is never more than a scan away.
2. Show the mechanism honestly: roles, handoffs, commits, stops.
3. No hype and no hacker costume: precise, calm, engineered.
4. Distinctive enough not to read as a stock template.
